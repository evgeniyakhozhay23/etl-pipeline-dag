## Построение ETL-пайплайна для приложения 

### Источник
Karpov Courses, курс "Симулятор Аналитика", https://karpov.courses/simulator

Данные с 02.05.2026 до текущего дня (обновляются в режиме реального времени). Данные предоставлены в рамках курса, хранятся в Clickhouse.

### Структура данных
Провожу работу с данными стартапа приложения с лентой новостей (feed_actions) и мессенджером (message_actions). 

Таблица feed_actions - информация о действиях пользователей в приложении ленты новостей:
- user_id - идентификационный номер пользователя
- post_id - номер поста
- action - вид действия пользователя в ленте (категориальная переменная). Значения - like и view.
- time - дата и время действия пользователя в ленте новостей
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение. Значения: iOS, Android
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента

Таблица message_actions - информация о пользователях мессенджера
- user_id - идентификационный номер пользователя
- receiver_id - идентификационный номер получателя
- time - дата и время отправки сообщения
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение
  
### Инструменты для работы
Python, выгрузка данных из Clickhouse, Aiflow, Github
### Условие и требования к заданию
**Цель:** Реализовать Airflow DAG, который ежедневно вычисляет метрики за предыдущий день.

**Задачи:**
1. Обработать данные из обеих таблиц. Выгрузка для каждой таблицы должна быть в отдельном таске.
- В feed_actions для каждого юзера посчитаем число просмотров и лайков контента.
- В message_actions для каждого юзера считаем, сколько он получает и отсылает сообщений, скольким людям он пишет, сколько людей пишут ему.
2. Объединить таблицы в отдельном таске
3. Для полученной таблицы рассчитать все метрики в разрезе по полу, возрасту и операционной системе. Три разных таска на каждый срез.
4. И финальные данные со всеми метриками записать в отдельную таблицу в ClickHouse, которая будет ежедневно дополняться новыми данными.

Структура итоговой таблицы:
- Дата - event_date
- Название среза - dimension
- Значение среза - dimension_value
- Число просмотров - views
- Число лайков - likes
- Число полученных сообщений - messages_received
- Число отправленных сообщений - messages_sent
- От скольких пользователей получили сообщения - users_received
- Скольким пользователям отправили сообщение - users_sent
